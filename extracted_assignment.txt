TASK 1 – GUI DESIGN REVIEW
Bloom’s Level: K4 – Analyse
Diagnose and Repair a Poor Event-Handling Design
6 Marks
A junior developer has built a student fee-payment window. Every button is handled by the same listener, and the complete program logic is written inside it.
public class FeeWindow extends Frame implements ActionListener {
  TextField regNo = new TextField(); TextField amount = new TextField();
  Button pay = new Button("Pay"), clear = new Button("Clear"), receipt = new Button("Receipt");
  public void actionPerformed(ActionEvent e) {
    if (e.getActionCommand() == "Pay") {
      double a = Double.parseDouble(amount.getText());
      Connection c = DriverManager.getConnection(URL, USER, PWD);
      c.createStatement().executeUpdate("INSERT INTO fees VALUES('" + regNo.getText() + "'," + a + ")");
      Thread.sleep(3000);          // wait for bank confirmation
      System.out.println("Paid");
    } else { regNo.setText(""); amount.setText(""); }
  }
}
Task 1.1 – Diagnose the Design | 2 Marks
Identify at least five design deficiencies in this code. Do not focus merely on syntax. Examine aspects such as:
Separation of interface and logic
String comparison of the action command
Handling of invalid or empty input
Database work performed on the event-dispatch thread and the effect of sleep() on the window
Feedback to the user
The Receipt button
Security of the SQL statement
Closing of the window and of the database connection
Checked exceptions that are not handled
For each deficiency, explain briefly what the user would experience or what could go wrong.
Task 1.2 – Repair the Design | 3 Marks
Redesign the program so that the window only collects input and shows results, and a separate FeeService class performs validation and payment. Present the class structure and rewrite the event handling.
Task 1.3 – Design Defence | 1 Mark
In not more than 100 words, explain why your redesign is easier to test and maintain.
Alternative Concept and Complexity Analysis
If, instead of one listener with an if–else chain on the action command, each button had its own listener object (or a Swing Action), what would the solution be? Analyse the time to dispatch an event for k buttons (up to k comparisons versus O(1)) and the space used by k listener objects.
Evidence Expected
A reasoned diagnosis, a corrected design and a concise justification.

Task 2.3 – Design the Handler Logic | 3 Marks

Task 2.4 – Trace the Event Sequence | 1 Mark

TASK 6 – DESIGN CHALLENGE
Bloom’s Level: K5 – Evaluate
Campus Event Registration Desktop Application
13 Marks
The cultural committee needs a desktop application to manage event registrations. Students register for events through a form; the committee views all registrations in a table, filters them by event and exports the list. The data is stored in a MySQL database. The application must remain responsive while data is loading, must reject invalid input clearly, and must not allow a student to register twice for the same event.
You are not given the design.
Stage 1 – Interpret the Problem | 2 Marks
Identify the users, the screens, the data and the rules. State the requirements as testable statements.
Stage 2 – Propose the Screen and Event Flow | 2 Marks
Sketch each screen, including a menu bar (MenuBar/JMenuBar), and draw the flow between screens and dialogs.
Stage 3 – Identify the Critical Design Decisions | 2 Marks
Identify where input validation, duplicate checking and database access occur, and how long-running database work is kept off the event-dispatch thread.
Stage 4 – Design the Classes and Handlers | 4 Marks
Present a class diagram separating the user interface, service and data-access (JDBC) layers, and pseudocode for the Register and Filter actions.
Stage 5 – Implement and Demonstrate | 3 Marks
Implement the application using Swing (JFrame, JPanel, JTextField, JComboBox, JTable, JMenuBar) with JDBC, and demonstrate normal, invalid and duplicate registrations.
Alternative Concept and Complexity Analysis
If all registrations were loaded into the JTable at once, instead of loading one page at a time using SQL LIMIT and OFFSET in a SwingWorker, what would the solution be?
